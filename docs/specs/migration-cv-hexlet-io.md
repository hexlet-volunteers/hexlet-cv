# Переезд cv.hexlet.io на новый стек

Эпик: #1307

## Зачем

На cv.hexlet.io сейчас работает старое Rails-приложение «Резюме программистов» на Heroku. В этом репозитории — новый продукт «Хекслет Карьера» (Java + React), но он нигде не развёрнут, и задач на сам переезд нет: майлстоуны M1–M7 описывают новые функции, а не замену работающего сайта.

Цель — переключить домен на новый стек, не потеряв пользователей, резюме и ссылки на них. Новые функции (вакансии, трекер, AI) добавляются уже после переезда.

## Что есть сейчас

| Слой | Состояние |
|---|---|
| Старый прод | Rails на Heroku. Публичные страницы: `/ru` (каталог резюме с поиском `?q` и пагинацией), `/ru/resumes/:id`, `/ru/users/:id`, `/ru/vacancies`, `/ru/users/sign_in`, `/ru/users/sign_up`. По id на главной — порядка 43 тыс. пользователей и 18 тыс. резюме (оценка). |
| Бэкенд | Spring Boot, схема `V1__init_schema.sql` повторяет таблицы старого приложения (users, resumes, resume_*, careers, vacancies и др.). Готова авторизация на JWT с ротацией refresh-токенов (#1215). |
| Фронтенд | React + Vite. Ни одного запроса к API: все данные из `frontend/src/shared/mocks/data.ts`. Реальные экраны — лендинг, вход, регистрация и 4 экрана кабинета, остальные 21 — заглушки. |
| Контракт API | Design First (#1106) начат: в TypeSpec описаны только истории. Связка REST + TanStack vs Inertia не решена (#1111). |
| Деплой | CI только собирает и проверяет. Есть инструкция для Render (#1043), но по 242-ФЗ база ПДн должна быть в РФ (#1233). |

## Минимальный объём для переключения домена

Новый сайт должен уметь всё, что сейчас реально используется на старом:

1. **Вход и регистрация** — уже в эпике #1120. Старые пароли должны работать (см. перенос данных).
2. **Резюме: создание, редактирование, публичная страница** — части эпика #1125, но публичной страницы резюме и профиля пользователя в задачах нет.
3. **Каталог резюме** с поиском — как на старой главной `/ru`.
4. **Перенос данных** из базы Heroku.
5. **Редиректы** со старых адресов.
6. **Прод-окружение** в РФ и автодеплой.

Вакансии, трекер, письма, AI-ревью и AI-собес в этот объём не входят.

## Перенос данных

- Источник — Postgres старого приложения на Heroku, приёмник — схема из `db/migration`. Перед переносом сверить схемы таблица к таблице: часть полей в новой схеме могла измениться.
- Пароли: Rails (Devise) хранит bcrypt-хэши. Spring Security читает bcrypt, поэтому хэши переносятся как есть, без сброса паролей. Проверить на тестовом пользователе.
- Сохранить id резюме и пользователей — на них завязаны внешние ссылки и редиректы.
- Перенос делается дважды: репетиция на копии базы и финальный прогон при переключении. Результат — отчёт по количеству строк в каждой таблице до и после.
- Персональные данные переносятся только в окружение, которое удовлетворяет #1233.

## Редиректы

| Старый адрес | Новый адрес |
|---|---|
| `/ru`, `/ru?q=…&page=…` | каталог резюме с тем же поиском |
| `/ru/resumes/:id` | публичная страница резюме `:id` |
| `/ru/users/:id` | публичный профиль `:id` |
| `/ru/users/sign_in`, `/ru/users/sign_up` | `/login`, `/register` |
| `/ru/vacancies` | `/` до появления раздела вакансий |
| `/en/...` | те же правила |

Все — 301. Удалённые и скрытые резюме — 410 или 404, не редирект на главную.

## Переключение домена

1. Репетиция переноса и проверка редиректов на стенде.
2. Объявление пользователям о дате переезда.
3. Старое приложение — в режим только для чтения.
4. Финальный перенос, сверка количества строк.
5. Переключение DNS cv.hexlet.io на новое окружение.
6. Мониторинг ошибок и 404 первые дни.
7. Откат: DNS обратно на Heroku, база Heroku не удаляется минимум месяц.
